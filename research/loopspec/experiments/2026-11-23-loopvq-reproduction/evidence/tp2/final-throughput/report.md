# Ouro-2.6B-Thinking 的 TP2 纯 decode 吞吐

固定 2,048 个输入 token，分别生成 1,024、2,048、4,096、8,192 个新 token，忽略 EOS。每个 batch 在同一对 A100-SXM4-80GB 上依次测 BF16 与 0.5-bit LoopVQ，DP=1、R4，LoopVQ 高精度窗口为 8+64。每次测量从整批共同到达的早期输出 token 计时到整批生成完毕，排除 prefill。每个可运行配置完整测三次，表内为三次中位数；加速比为两个中位数之比。实际 batch 全程符合目标，每个记录的 decode 步均使用 full CUDA graph，目标 batch 无 padding。

当前 BF16 池最多容纳 92,432 个 token。bs=16、4K 或 8K 新增输出分别需要 98,304 和 163,840 个 token。这两个配置保留 VQ 绝对吞吐，BF16 容量按本次服务配置记录。

1K 和 2K 输出的十个配对都低于 1×。8K 输出、bs=1 的吞吐增益为 8.25%，而 bs=4 仍下降 4.36%。同一个 8K 请求按输出位置切分，bs=1 的首段倍率为 0.983×，末段为 1.207×；早期的计算和调度开销稀释了后半段的收益。TP2 的这些倍率来自未挂 profiler 的真实服务。此前 TP1 profile 定位的高精度 attention、合并开销和图间间隔可解释该趋势，TP2 上各开销的精确占比仍需独立采样。
